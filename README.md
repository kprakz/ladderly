# Pathfinder

Type any skill or topic ("guitar", "machine learning", "public speaking") and get a short, structured learning path from zero to competent, generated by Claude.

- 4–6 ordered stages, each with concepts, practice tasks, a testable "ready to move on" checkpoint and suggested kinds of resources
- A finish-line project and common pitfalls
- Tick off checkpoint items and track progress per stage and overall
- Paths and progress are saved in your browser (localStorage)
- Live streaming preview while the path is generated, and friendly errors with a retry button
- Responsive, with light and dark mode

## Setup

Requirements: Node.js 20.9 or newer.

```bash
npm install
cp .env.example .env.local
```

### Demo mode (free, no API key)

With `DEMO_MODE=true` in `.env.local` (the default in `.env.example`), or whenever no `ANTHROPIC_API_KEY` is set, the app doesn't call the API. A banner at the top of the page shows when demo mode is on. It streams built-in sample paths instead, so everything else (timeline, checkboxes, progress, history, dark mode) works for free.

- Hand-written samples: **guitar**, **public speaking** and **python**. A topic containing one of those words gets that sample.
- Any other topic gets a generic template with the topic's name filled in, marked `[Demo]` in its summary.
- The level, hours and goal options are ignored in demo mode.

The samples live in `src/lib/demo.ts`. Add more there.

### Real generation with Claude

Set `DEMO_MODE=false` and add an [Anthropic API key](https://console.anthropic.com/) to `.env.local`:

```
DEMO_MODE=false
ANTHROPIC_API_KEY=sk-ant-...
```

Restart the dev server after changing `.env.local`. The key is only read on the server (`src/app/api/path/route.ts`) and is never sent to the browser. `.env.local` is git-ignored.

## Deploy (free, demo mode)

1. Push the repo to GitHub.
2. On [vercel.com](https://vercel.com), sign in with GitHub, click **Add New → Project** and import the repo.
3. Keep the default settings (Vercel detects Next.js) and click **Deploy**.

Don't add an `ANTHROPIC_API_KEY` environment variable in Vercel. Without it the site stays in demo mode and can never make paid API calls.

## How it works

1. The form posts `{ topic, level?, hoursPerWeek?, goal? }` to `POST /api/path`, which is validated with zod.
2. The route streams a request to Claude (`claude-opus-5`) with **structured outputs**: the zod schema in `src/lib/schema.ts` becomes the JSON schema, so Claude has to return JSON in that shape.
3. As text arrives, the route forwards it to the browser as newline-delimited JSON (`{"type":"delta"}`). The loading panel shows the stage titles as they appear.
4. When Claude finishes, the server parses the full JSON and validates it against the zod schema, including the rules the JSON schema can't enforce, such as "4–6 stages" and "exactly 3 pitfalls". It then sends either `{"type":"done","path":...}` or `{"type":"error","message":...}`.
5. The browser saves the path to localStorage and renders it as a timeline.

The request also sets `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`). If Claude's safety classifiers decline a request, the API retries it on Anthropic's recommended fallback model instead of failing. To turn this off, remove those two lines.

## Project structure

```
src/
  app/
    api/path/route.ts   # Server route: calls Claude, streams NDJSON, validates with zod
    layout.tsx          # Root layout + no-flash theme script
    page.tsx            # Main page: form, loading/error states, path view, history
    globals.css         # Tailwind + class-based dark mode
  components/
    PathForm.tsx        # Topic input and optional level / hours / goal
    PathView.tsx        # Summary, overall progress, timeline, finish line, pitfalls
    StageCard.tsx       # One stage in the timeline, with checkpoint checkboxes
    StatusPanels.tsx    # Loading (live stage preview) and error (retry) panels
    History.tsx         # Saved paths list
    ProgressBar.tsx
    ThemeToggle.tsx
  lib/
    schema.ts           # zod schemas + types shared by server and client
    prompt.ts           # System prompt and user prompt builder
    demo.ts             # Sample paths served when DEMO_MODE=true
    generate.ts         # Client helper that reads the NDJSON stream
    storage.ts          # localStorage-backed store (useSyncExternalStore)
```

## Customizing

- **Model / effort:** edit `model` and `output_config.effort` in `src/app/api/path/route.ts`. `effort: "medium"` keeps responses quick. Raise it for more considered paths.
- **Path shape:** edit `LearningPathSchema` in `src/lib/schema.ts`. The prompt schema and the validation both come from it.
- **Tone / rules:** edit `SYSTEM_PROMPT` in `src/lib/prompt.ts`.
- **Reset saved data:** clear the `pathfinder:paths` and `pathfinder:theme` localStorage keys.
